# Design

## Context

See `proposal.md` for motivation. The review ran at `e0f611a` and its findings are numbered F1 to
F19 in `tasks.md`. Constraints that shape the approach:

- Bundles under `src/anylumino/static/**` are generated by `npm run build` and committed. CI fails
  when they differ from a fresh build, so every frontend task ends with a rebuild.
- Frontend tests run with `node --test` on pure functions only. Nothing runs in a browser today,
  although `playwright` is a dev dependency and `scripts/docs_examples.py` already starts
  JupyterLab and drives headless Chromium.
- `openspec/specs/` is empty. `add-openui-workbench` is complete but not archived, so the three
  workbench deltas here use ADDED requirements on its capability paths.
- `option_trader` uses anylumino. The breaking changes need its callers updated in the same task.
- Findings 5, 6, and 9, and three picker defects, were traced through source and never observed
  in a browser. Each needs a failing browser test before its fix.

## Goals / Non-Goals

**Goals:**

- Fix F1 to F19, each with a regression test that fails before the fix.
- Remove the four shared causes: one place that permutes per-child state, one option rule, one
  home per attribute, one workbench turn lifecycle.
- Make the Python/JS contract checkable by a test.

**Non-Goals:**

- A change to how a widget looks, beyond the defects listed.
- Retiring the native pickers or rebuilding them on Astryx inputs.
- These review open risks, which need evidence this change does not gather: Codex receiving the
  system prompt only once, wide data frames in the argv, `load` path resolution in marimo, and a
  pruned agent conversation id.
- Reducing the node process count of the OpenUI tool.

## Decisions

### D1. Browser tests reuse the documentation capture harness

Add a `tests/browser/` pytest package marked `browser`. It reuses the `jupyterlab()` context
manager and notebook runner from `scripts/docs_examples.py`, moved into an importable module that
both use. Each test runs a small notebook cell and asserts on the DOM and on kernel state.
`make test-browser` runs the lane; `make test` and plain `pytest` exclude the marker. CI gains a
`playwright install chromium` step and runs the lane.

Alternative: jsdom under `node --test`. Rejected: F6 depends on real layout (`display: none`,
measured sizes) and on anywidget's host, which jsdom does not provide.

This group comes first so every later frontend fix starts from a failing browser test.

### D2. One function permutes all per-child state

`KeyedChildren` gains a class attribute naming its per-child list traits (`("stretches",)`,
`("sizes",)`, `("areas",)`, empty by default) and one private method that applies a permutation
with insertions and removals to `child_keys`, `titles`, and those lists inside one `hold_sync`.
`add_widget`, `remove_widget`, `move_widget`, and `_rekey_children` call it. `_drop_child_metadata`
and its three overrides are deleted.

An empty list stays empty, because empty means "use the layout default". A non-empty list gets a
neutral entry on add: stretch `0`, an empty area, or the mean of the current split sizes.

The Astryx `AccordionPanel` open keys (F14) are keyed by child key, not position, so they are
pruned in an `_adopt_children`-style hook, not through the permutation.

Alternative: store per-child settings as one dict per child. Rejected: it changes three public
traits and the wire format for no gain over a shared permutation.

### D3. Option values are strings, decided in Python

`_option_records` becomes the only option normalizer for Astryx widgets and stringifies bare
scalars as it already does pairs and mapping entries. `SelectionSlider` takes its default from the
normalized record. The frontend `itemValue` and `searchableItems` keep their `String(...)` calls
as a no-op guard. `common.options_tuple` and `option_value` have no caller outside `common.py`;
they stay, since they are importable, and get no new callers.

Alternative: keep the caller's value type and translate at the boundary with an id-to-value map.
Rejected: pairs and mappings already yield strings, so this would change the larger group to
preserve the smaller one, and it adds a map that must survive `props` reassignment.

This is the first breaking change. `SelectionSlider([1, 2, 3]).value` is `"1"`.

### D4. The trait is the home for shared attributes

`label`, `variant`, `disabled`, and `icon` are sent as traits only. Wrappers stop writing them
into `props` (for example `DropdownMenu`'s `button={"label", "variant"}`), and each frontend spec
reads the trait. Component-specific values stay in `props`. The contract test in D6 enforces the
rule in both directions: a synced trait must be read, and a `props` key must not shadow a trait
name.

Alternative: move everything into `props`. Rejected: `label` and `disabled` are documented traits
that users assign and observe.

This is the second breaking change, for code that reads `widget.props["label"]`.

### D5. Component table split by family

`componentProps`, `componentChildren`, and the five name registries become one table:

```js
export const SPECS = {
  Selector: { component: Selector, props: (ctx) => ({...}), children: "none" },
};
```

`ctx` carries `model`, `props`, and the shared trait values. The table lives in
`static/astryx/components/{inputs,surfaces,data,layout,chat}.mjs`, mirroring the Python modules,
with `astryx_widget.js` keeping the model view, child mounting, and theme code. esbuild already
bundles from one entry, so the output files and loaders keep their names. A name missing from the
table renders the error required by the spec.

The move is mechanical and comes before the behavior fixes in the same files, so each fix lands
in its final location. The browser smoke test from D1 renders every component before and after.

### D6. Contract test reads both sides as text

A pytest test extracts, from the frontend sources, every `model.get("...")`, every watched trait
name, every `SPECS` key, and every message `type` sent or handled. It compares them with the
synced traits, `component_name`s, and message handlers found by importing the Python classes. The
frontend exposes its trait reads through one accessor so the regular expression has one shape to
match.

Alternative: generate a manifest at build time. Rejected: a second generated file to keep
current, when the sources are small enough to scan.

`ComponentWidget` then loses each synced trait the test reports as unread (the review listed
`tag`, `selected`, `indeterminate`, `placement`, `orientation`, `icon_src`, `icon_size`, and
`attributes`; the test decides the final list). `ComponentWidget` stays as the exported base of
`astryx.Widget`. This is the third breaking change.

### D7. A child's abort signal belongs to its slot

The Astryx child mount gives each slot element its own `AbortController`, as
`static/layout/layout_panel.js` already does. A slot that leaves the DOM aborts its child view. A
slot that is only hidden keeps its element: `SplitPanel` panes and inline `Dialog` content stay
mounted and are hidden with CSS, which is what the `astryx/layout.py` docstring already promises.
For `Dialog`, the wrapper keeps the content host outside the Astryx dialog body and moves it in
when open, so Astryx returning `null` while closed does not unmount it.

This also closes the open risk of a superseded render writing into a cleared slot, since the
cleared slot's signal is aborted.

### D8. Search inputs keep an item cache

The search view keeps a `Map` from id to item for every item it has shown or created, and builds
the controlled value from static items plus that cache. The search source object is memoized on
the model, so a re-render does not replace it and cancel an in-flight search. The cache is browser
state: a fresh view of a widget whose value is not in its static items shows the id as its label.

### D9. One turn lifecycle in the workbench

A single async context manager owns a turn. On entry it refuses a second turn, sets `running`,
clears `runner.stopped`, and registers the workbench as the owner of its session name. On exit,
in a `finally`, it records one outcome (applied, not applied, failed, stopped), finalizes tool
call statuses, reports any unexpected exception to the chat, saves the session, and clears
`running`. `submit`, `ask_agent`, `import_file`, and `restore` run inside it and lose their
hand-written flag handling. `report_reconcile` reads the recorded outcome.

Stop is checked at each await boundary through one function, so a stop during merge, parse, or
apply ends the turn as stopped.

Session takeover uses a module-level registry of session name to running workbench. A new
workbench for a registered name stops that turn and awaits its end first. In marimo the turn loop
cancels its pending task and terminates the process before `loop.close()`.

`add_message`, `update_reply`, and `set_messages` take one lock around their read-modify-write.

### D10. Typed OpenUI results

`openui.parse` and its siblings return a frozen dataclass (`errors`, `incomplete`, `unresolved`,
and the payload) built from the tool's JSON, and raise on a missing field. `apply` rejects a
result with unresolved names. Dictionary indexing by string goes away, which is what let
`unresolved` go unread.

### D11. Agent failure reporting

The event loop in `workbench.py` keeps the first `Failed` event. `agents.py` starts the stderr
reader before it writes the prompt, and treats `BrokenPipeError` and `ConnectionResetError` on
stdin as "the process exited early": it stops writing, waits for the process, and reports stderr.

### D12. Catalog from signatures

`catalog.py` resolves constructor annotations with `typing.get_type_hints` and maps enum classes
and `Literal` types to option values, replacing string matching on annotation text and the
numpydoc `{...}` type parsing. The keyword-to-Astryx-prop renames, now recovered by a regular
expression over `inspect.getsource`, move to a mapping declared beside each wrapper that renames.
Descriptions still come from the docstring, since they are prose for the agent and cannot change
what is accepted.

String unions for pass-through Astryx props exist only in the docstring "Astryx Props" section
today. They move to the same per-wrapper declaration. The regenerated skill files are diffed
against the committed ones; the diff must show no lost prop or value.

### D13. Smaller frontend decisions

- Scroll box gap: `${Number(model.get("spacing") ?? 8)}px`.
- Separators: one predicate, `item.separator || item.type === "separator"`, used by the toolbar
  and the menu builder.
- Command icons: the icon class includes a per-widget id, and the observer watches the widget's
  root and the menus it opens, not `document.body`.
- Bundle loader: a 10 second timeout rejects the shared promise, which already clears itself on
  rejection so the next widget retries. The loader source is `scripts/build-frontend.mjs`; the
  `.loader.js` files are generated.
- anywidget: keep the private import, wrapped so an `ImportError` names the anywidget version.
  The dependency stays `>=0.11.0`; an upper bound would block users on a release that still works.

## Risks / Trade-offs

- [Three breaking changes in one release] -> Ship as 0.7.0 with a CHANGELOG migration section,
  and update `option_trader` in the same tasks.
- [The component table move touches about 800 lines] -> Do it as its own task with no behavior
  change, verified by the all-components browser smoke test before and after.
- [Browser tests are slow and can flake] -> One JupyterLab per session, DOM assertions that wait
  on a condition, and a separate lane so `pytest` stays fast.
- [F5, F6, F9 may behave differently in a browser than traced] -> Each fix starts from a failing
  browser test. If the test passes unfixed, record the finding as rejected in `tasks.md` and skip
  the fix.
- [Keeping hidden dialog content mounted costs memory] -> It matches the documented contract and
  the Lumino panels' behavior.
- [The contract test reads source with regular expressions] -> One accessor shape for trait reads
  keeps the pattern stable, and the test fails closed on a file it cannot parse.
- [Session takeover could stop a turn the user wanted] -> Only within one kernel and only for the
  same session name, where two turns would overwrite each other's saved result anyway.

## Migration Plan

1. Land groups in `tasks.md` order; each leaves the suite green and bundles current.
2. Release as 0.7.0. The CHANGELOG lists the three breaking changes with before and after code.
3. Rollback is a revert of the release; saved sessions keep their format, with `cwd` rewritten
   only when one is passed.
4. Archive `add-openui-workbench` before this change so the workbench deltas merge into its specs.
