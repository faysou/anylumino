# Specification: `anylumino` Generative UI Workbench with Local CLI Agent Bridge

## 1. Project Overview
Build a stateful, notebook-native Generative UI Workbench using **`anylumino`** (Lumino layout containers built on `anywidget`) and **`anylumino.astryx`** (UI components and theming).

The workbench renders as a multi-pane application inside JupyterLab, Jupyter Notebook, VS Code, or Marimo:
- **Left Pane (`ax.Chat`):** Interactive chat interface connected asynchronously to a local CLI coding agent (`claude` or `codex`).
- **Right Pane (`al.TabPanel`):**
    1. **Live UI Canvas:** Dynamically mounts and updates `anylumino` + `astryx` widget trees generated by the agent.
    2. **Callbacks Code Pane (`callbacks.py`):** Displays and edits the Python event handlers (`observe` callbacks) bound to the live widgets, supporting instant hot-reloading and access to notebook globals (e.g., Pandas/Polars DataFrames).
- **Session Persistence & Recovery:** Named sessions synchronize with native CLI sessions (`claude -n` / `--resume`) and persist a local JSON sidecar (`~/.anylumino_sessions/<session_name>.json`) containing chat history, the declarative UI AST, and the Python callback code.
- **Standalone Python Exporter:** Deterministically compiles the current declarative UI AST and the Python callback code into a self-contained, dependency-free `<session_name>_app.py` script.

## 3. Agent Output Protocol (Dual-Block Contract)

When the local agent (`claude` or `codex`) responds to a user prompt, it is instructed via system prompt to return:
1. A brief conversational explanation (rendered in `ax.Chat`).
2. An **`openui-json`** fenced block containing the declarative `anylumino` + `astryx` component tree.
3. A **`python-callbacks`** fenced block containing Python event handler functions.

### 3.1 Declarative UI Schema (`openui-json`)
Every interactive or state-targeted widget must have a unique string `"id"`. Event hooks (`"on_click"`, `"on_change"`) reference function names defined in the `python-callbacks` block.

**Supported Layout Containers (`anylumino`):**
- `SplitPanel`: `{"type": "SplitPanel", "id": "...", "orientation": "horizontal" | "vertical", "children": [...]}`
- `TabPanel`: `{"type": "TabPanel", "id": "...", "titles": ["Tab 1", "Tab 2"], "children": [...]}`
- `BoxPanel`: `{"type": "BoxPanel", "id": "...", "direction": "top-to-bottom" | "left-to-right", "children": [...]}`
- `DockPanel`: `{"type": "DockPanel", "id": "...", "children": [...]}`

**Supported Leaf Components (`anylumino.astryx`):**
- `Brand`: `{"type": "Brand", "name": "desk", "tokens": {"color-accent": ["#0057b8", "#79b8ff"]}}`
- `Card`: `{"type": "Card", "id": "...", "title": "...", "description": "...", "children": [...]}`
- `Button`: `{"type": "Button", "id": "...", "label": "...", "variant": "primary" | "secondary", "on_click": "handler_fn_name"}`
- `Input`: `{"type": "Input", "id": "...", "placeholder": "...", "value": "...", "on_change": "handler_fn_name"}`
- `Textarea`: `{"type": "Textarea", "id": "...", "value": "...", "rows": 8, "on_change": "handler_fn_name"}`
- `Text`: `{"type": "Text", "id": "...", "content": "..."}`
- `ExternalWidget`: `{"type": "ExternalWidget", "id": "...", "notebook_var": "fig_or_table_name"}` (mounts an existing `anywidget` from `notebook_scope`).

### 3.2 Callback Function Signature (`python-callbacks`)
All generated Python callbacks must adhere to a standard two-argument signature:
```python
def <handler_name>(change: dict, widgets: dict[str, Any]):
    """
    change: standard traitlets observe change dictionary (e.g. change["new"])
    widgets: dict mapping widget "id" strings from openui-json to live anywidget instances
    """
```
In addition, callbacks may call `ask_agent(prompt: str)` (injected into the callback execution scope) if a button click should trigger a follow-up turn with the local agent (`@ToAssistant` behavior).

## 4. Core Module Specifications

### Module 1: Local CLI Agent Bridge (`agent_bridge.py`)
- Must use `asyncio.create_subprocess_exec` so CLI calls never block the Jupyter/Marimo event loop.
- Support both `claude` (Claude Code) and `codex` (OpenAI Codex CLI).
- **Session Naming & Resuming:**
    - First turn on a new session: `claude -n <session_name> -p <prompt> --append-system-prompt <SYSTEM_PROMPT>`
    - Subsequent or recovered turns: `claude --resume <session_name> -p <prompt>`
    - Codex equivalent: `codex exec` / `codex exec resume <session_name> <prompt>`
- **Parser (`parse_agent_response`):**
    - Uses regex to extract `openui-json` (parsed via `json.loads`) and `python-callbacks` (raw Python string).
    - Strips both fenced code blocks from the user-facing text returned to `ax.Chat`.
    - If the user only asks to tweak callback logic, `openui-json` may be omitted (keep existing UI tree); if the user only changes layout, `python-callbacks` may be omitted (keep existing callbacks).

### Module 2: Widget Interpreter & Live Callback Binder (`interpreter.py`)
- **`build_widget_tree(ui_spec: dict, notebook_scope: dict) -> tuple[AnyWidget, dict[str, AnyWidget], list[BindingSpec]]`:**
    - Recursively instantiates `al.*` and `ax.*` widgets.
    - Registers every widget with an `"id"` into `widget_registry: dict[str, AnyWidget]`.
    - Collects a list of `BindingSpec(widget_id, widget_instance, trait_names, handler_name)` for any node specifying `on_click` (observes `["clicks", "value"]`) or `on_change` (observes `["value"]`).
- **`bind_callbacks(cb_code: str, widget_registry: dict, bindings: list[BindingSpec], notebook_scope: dict, ask_agent_fn: Callable)`:**
    - Builds an execution namespace: `ns = {**notebook_scope, "al": al, "ax": ax, "ask_agent": ask_agent_fn}`.
    - Executes `exec(cb_code, ns)`.
    - Iterates over `bindings`, calls `widget.unobserve_all()`, and attaches:
      ```python
      widget.observe(lambda change, fn=ns[b.handler_name]: fn(change, widget_registry), names=b.trait_names)
      ```
    - Catches and displays syntax or runtime errors in the workbench status bar without crashing the kernel.

### Module 3: Session Persistence Manager (`session_store.py`)
- Stores session sidecar files in `~/.anylumino_sessions/<session_name>.json`.
- **Schema of `<session_name>.json`:**
  ```json
  {
    "session_name": "sales-dashboard",
    "agent_cli": "claude",
    "updated_at": "2026-10-18T16:00:00",
    "messages": [
      {"role": "user", "content": "..."},
      {"role": "assistant", "content": "..."}
    ],
    "ui_spec": { ... },
    "callbacks_code": "def on_click(change, widgets):\n    ..."
  }
  ```
- **Recovery Behavior:**
    - Initializing `Workbench(session_name="sales-dashboard")` checks if `~/.anylumino_sessions/sales-dashboard.json` exists.
    - If found, it immediately restores `ax.Chat.messages`, populates the Callbacks Editor with `callbacks_code`, rebuilds the right-pane `anylumino` widget tree from `ui_spec`, re-binds the callbacks, and marks the CLI session as initialized so the next message uses `--resume "sales-dashboard"`.

### Module 4: Deterministic AST-to-Python Exporter (`exporter.py`)
- **`compile_to_standalone_py(ui_spec: dict, callbacks_code: str, session_name: str) -> str`:**
    - Walks `ui_spec` bottom-up without needing an LLM call and emits clean, PEP-8 formatted Python code.
    - Emits the `callbacks_code` block at the top of the file.
    - Generates a `create_ui() -> tuple[AnyWidget, dict[str, AnyWidget]]` function that:
        1. Instantiates every `anylumino` and `astryx` widget using readable variable names (using the node's `"id"` if valid Python identifier, otherwise `<type>_<counter>`).
        2. Populates `widgets = {"<id>": <var>, ...}`.
        3. Wires `.observe(lambda change: <handler_name>(change, widgets), names=[...])` for every `on_click` / `on_change` in the spec.
        4. Returns `root_widget, widgets`.
    - Appends top-level `ui, widgets = create_ui()` so the exported `.py` file can be imported or run directly in Jupyter or Marimo.

## 5. Target Exported File Format (`<session_name>_app.py`)

The exporter in Module 4 must produce output matching this structure:

```python
"""
Auto-generated anylumino + Astryx Application
Session: sales-dashboard
"""
import anylumino as al
import anylumino.astryx as ax

# =====================================================================
# 1. Event Callbacks
# =====================================================================
def on_calculate_clicked(change, widgets):
    region = widgets["region_input"].value.strip() or "All"
    widgets["result_card"].description = f"Active region: {region}"


# =====================================================================
# 2. UI Layout & Binding Builder
# =====================================================================
def create_ui():
    widgets = {}

    region_input = ax.Input(placeholder='Enter region...', value='')
    widgets['region_input'] = region_input

    filter_btn = ax.Button(label='Calculate', variant='primary')
    widgets['filter_btn'] = filter_btn

    result_card = ax.Card(title='Regional Revenue', description='Ready')
    widgets['result_card'] = result_card

    root_box = al.BoxPanel(direction='top-to-bottom')
    root_box.children = [region_input, filter_btn, result_card]
    widgets['root_box'] = root_box

    # Wire callbacks
    filter_btn.observe(
        lambda change: on_calculate_clicked(change, widgets),
        names=['clicks', 'value']
    )

    return root_box, widgets


ui, widgets = create_ui()
```

## 7. Implementation Milestones & Verification Criteria

1. **Milestone 1 — Interpreter & Callback Binder:**
    - Pass a mock `ui_spec` and `callbacks_code` string to `interpreter.py`.
    - Verify that `anylumino` panels and `astryx` components render, `widget_registry` is populated, and clicking an `ax.Button` executes the callback and updates a sibling `ax.Card`.
2. **Milestone 2 — Exporter:**
    - Run `compile_to_standalone_py()` on the mock spec and execute the generated `.py` file to verify `ui, widgets = create_ui()` runs without errors and preserves interactivity.
3. **Milestone 3 — Local CLI Bridge & Session Persistence:**
    - Connect `agent_bridge.py` to `claude` (with `-n` and `--resume`) and `session_store.py`.
    - Verify that sending a message saves `~/.anylumino_sessions/<name>.json` and re-instantiating `Workbench(session_name="<name>")` recovers both the chat and the live widget tree.
4. **Milestone 4 — Full Workbench Assembly (`workbench.py`):**
    - Assemble the `al.SplitPanel` (Left: `ax.Chat`, Right: `al.TabPanel` with `Live UI` and `Callbacks (.py)`).
    - Verify the **Hot-Reload Callbacks** button updates widget behavior in-place after manual edits in the `ax.Textarea` code pane, and **Export `.py`** writes the standalone file to disk.
